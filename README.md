# FIRST® Kazakhstan — сайт

Статический сайт (HTML + CSS + JS) без сервера. Оформление воспроизведено по скриншотам firstrobotics.kz (веб и мобильная версия), сезон FIRST® CANOPY™ 2026–2027.
Открыть на компьютере: распакуйте архив и откройте `index.html` двойным щелчком.

## Что обновляется само
Источник всего — официальная Google-таблица расписания
(docs.google.com/spreadsheets/d/1QJbpsCGQfsV_idUxsbKhKHm1SgQgFZAqQCVM67HY6VY). Сайт сверяется с ней каждый час и после ручного запуска,
а с настройкой из раздела «Мгновенное обновление при правке таблицы» — через 1–2 минуты после правки.
Таблица должна оставаться открытой по ссылке («Все, у кого есть ссылка — читатель»).

- **События и регистрация** — вкладки расписания (Kick-Off, Scrimmages, Regional, …).
  Меняете в таблице дату, место, категорию или ссылку на форму — это же будет на сайте.
- Прошедшие события (по дате или со статусом «Өтілді» в таблице) с сайта исчезают сами.
- Каждая форма регистрации проверяется. Если форма закрыта или её заголовок относится к другому событию
  (например, прошлогодняя форма), кнопка на сайте не показывается. Список таких форм — в журнале запуска (Actions).
- **Тема сезона, логотип, видео, правила** — вкладка **«Сайт»** (см. ниже). Пока такой вкладки нет, сайт показывает тексты, встроенные в `assets/js/data.js`.
- **Новости** — основной путь: пост в Telegram-канале @firstroboticskz с хэштегом **#сайт**. Первая строка поста становится заголовком (до 110 знаков), остальной текст – подводкой (до 220 знаков), фото или обложка видео – картинкой, карточка ведёт на сам пост; хэштеги на сайте не показываются. Ограничения по числу нет: на сайт попадают все посты с хэштегом (`telegram_max_news: 0` в `tools/config.json`; чтобы хранить только N последних, впишите число). При каждом обновлении просматриваются ~120 последних сообщений канала, поэтому хэштег ставьте на свежие посты. Чтобы убрать новость с сайта, удалите хэштег или пост. Вкладка **«Новости»** в таблице (см. ниже) – запасной вариант, пользоваться ею не обязательно. На главной показываются 8 последних новостей, на странице «Все новости» (`news.html`) – все.
  (заголовок — первая строка поста, фото — из поста; убрали хэштег или удалили пост — новость уйдёт с сайта).

по ней сайт понимает, что это за строка. Порядок строк не важен, ненужные строки можно оставить пустыми или удалить.

- **Сезон** — название сезона (до 60 знаков). **Тема** — одно-два предложения о теме сезона (до 300 знаков на язык);
  если казахский или английский текст не заполнен, показывается русский.
- **Логотип** — ссылка на картинку PNG, JPEG или WebP не больше 3 МБ. Проще всего загрузить файл на Google Диск,
  нажать «Поделиться» → «Все, у кого есть ссылка» и вставить ссылку (подходят и картинки с firstinspires.org, firstrobotics.kz, ustem.kz).
  Сайт сохранит файл как `assets/img/season.png` (или `.jpg`, `.webp`); поменяли ссылку или сам файл — сменится и логотип.
- **Видео** — ссылка на YouTube (youtube.com или youtu.be).
- **Правила** — ссылка на правила сезона: B — русская версия, C — казахская (можно заполнить одну). **Письмо** — официальное письмо «Дарын».
  **Расписание** — ссылка на расписание (если пусто — сама таблица). Для этих трёх принимаются только ссылки на docs.google.com,
  drive.google.com, firstinspires.org, firstlegoleague.org, first.global, firstrobotics.kz и ustem.kz.
- **FLL / FTC / FRC** — названия тем программ в этом сезоне (до 40 знаков), например BIOGLOW / BIOBUZZ / BIOCORE.
- Строка с незнакомым названием параметра пропускается, в журнале запуска (Actions) появляется замечание. Удалили вкладку — сайт вернётся к встроенным текстам.

## Публикация на GitHub Pages (через браузер)
1. На github.com: **New repository** → имя, например, `first-kazakhstan` → **Public** → **Create repository**.
2. На странице нового репозитория нажмите ссылку **uploading an existing file** (позже это **Add file → Upload files**).
   Перетащите из распакованной папки только `index.html`, `news.html`, `README.md` и папки `assets` и `tools` (97 файлов, это меньше лимита GitHub в 100 файлов за раз; скрытый пустой файл `.nojekyll` загружать не обязательно).
   Папку `.github`, если она видна, на этом шаге не загружайте — она добавится на шаге 4. Нажмите **Commit changes**.
3. **Settings → Pages → Build and deployment → Source: GitHub Actions**. Этот шаг нужен до следующего, иначе первый запуск не сможет опубликовать сайт.
4. Файл автообновления: **Add file → Create new file**. В поле имени впишите `.github/workflows/update-site.yml`,
   вставьте весь текст из файла `tools/update-site.yml` и нажмите **Commit changes**. Обновление запустится само (вкладка **Actions**).
   Если папка `.github` уже загрузилась на шаге 2, этот файл уже есть: просто запустите **Actions → «Обновление сайта» → Run workflow**.
5. Через 1–2 минуты сайт откроется по адресу `https://ВАШ-ЛОГИН.github.io/first-kazakhstan/` (ссылка видна в Settings → Pages).
6. Когда адрес сайта известен, откройте `index.html` (значок карандаша) и в строке `<meta property="og:image" content="assets/img/im2-hero.jpg">`
   замените `assets/img/im2-hero.jpg` на полный адрес этой картинки, например `https://ВАШ-ЛОГИН.github.io/first-kazakhstan/assets/img/im2-hero.jpg`.
   Тогда при отправке ссылки на сайт в Telegram и WhatsApp будет показываться картинка (предпросмотр ссылки требует полный адрес).
   Если запуск в Actions отмечен красным, проверьте шаг 3 и нажмите **Actions → «Обновление сайта» → Run workflow**.

Дальше ничего делать не нужно: сайт проверяет таблицу и Telegram каждый час.
Обновить сразу — **Actions → «Обновление сайта» → Run workflow** (или настройте сигнал из таблицы — следующий раздел).

## Мгновенное обновление при правке таблицы
Без этой настройки сайт замечает правки в таблице в течение часа. Чтобы правки попадали на сайт через 1–2 минуты, таблица сама
сообщает GitHub об изменении. Настраивается один раз, минут за десять; нужны права владельца репозитория и редактора таблицы.

1. **Ключ для GitHub.** На github.com: значок профиля → **Settings** → внизу слева **Developer settings** → **Personal access tokens** →
   **Fine-grained tokens** → **Generate new token**. Token name: `sheet-updated`; Expiration: максимальный срок (1 год);
   **Repository access: Only select repositories** → выберите репозиторий сайта; **Permissions → Repository permissions → Contents: Read and write**.
   Нажмите **Generate token** и скопируйте ключ — он показывается один раз.
2. **Скрипт в таблице.** Откройте таблицу → **Расширения → Apps Script**. Удалите текст в редакторе, вставьте код ниже, замените `OWNER/REPO`
   на владельца и имя репозитория (как в адресе `github.com/OWNER/REPO`) и нажмите **Сохранить** (значок дискеты).
3. **Ключ — в свойства скрипта.** Слева **Настройки проекта** (шестерёнка) → **Свойства скрипта** → **Добавить свойство**:
   имя `GITHUB_TOKEN`, значение — скопированный ключ → **Сохранить свойства скрипта**.
4. **Триггер.** Слева **Триггеры** (будильник) → **Добавить триггер**: функция `sheetChanged`, источник события «Из таблицы»,
   тип события «При изменении» → **Сохранить**. Google попросит разрешения — выберите свой аккаунт и нажмите **Разрешить**
   (если появится «Приложение не проверено»: **Дополнительные настройки → Перейти к проекту**).
5. **Проверка.** Измените любую ячейку. Через минуту во вкладке **Actions** репозитория появится запуск «Обновление сайта»
   с пометкой `repository_dispatch`, ещё через 1–2 минуты сайт обновлён. Если запуска нет: в редакторе Apps Script выберите
   функцию `sendSignal`, нажмите **Выполнить** и посмотрите «Журнал выполнения» — там будет ответ GitHub.

```javascript
// Сообщает GitHub, что таблица изменилась, и сайт обновляется сразу, а не по расписанию.
// Сигнал уходит не чаще раза в 2 минуты; правки, сделанные за эти 2 минуты, уходят одним сигналом после паузы.
var REPO = 'OWNER/REPO';   // ← владелец и имя репозитория, например 'ivanova/first-kazakhstan'

function sheetChanged(e) {                       // срабатывает при каждой правке таблицы (триггер «При изменении»)
  var cache = CacheService.getScriptCache();
  if (cache.get('sent')) {                       // сигнал уже отправлен меньше 2 минут назад —
    cache.put('again', '1', 600);                // запомним, что после паузы нужен ещё один
    return;
  }
  sendSignal();
}

function sendSignal() {
  var cache = CacheService.getScriptCache();
  cache.put('sent', '1', 120);
  cache.remove('again');
  var token = PropertiesService.getScriptProperties().getProperty('GITHUB_TOKEN');
  if (!token) { console.warn('Нет свойства GITHUB_TOKEN (Настройки проекта → Свойства скрипта)'); return; }
  var r = UrlFetchApp.fetch('https://api.github.com/repos/' + REPO + '/dispatches', {
    method: 'post',
    contentType: 'application/json',
    headers: { 'Authorization': 'Bearer ' + token, 'Accept': 'application/vnd.github+json' },
    payload: JSON.stringify({ event_type: 'sheet-updated' }),
    muteHttpExceptions: true
  });
  if (r.getResponseCode() === 204) console.log('GitHub принял сигнал, сайт обновится через 1–2 минуты');
  else console.warn('GitHub ответил ' + r.getResponseCode() + ': ' + r.getContentText().slice(0, 200));
  ScriptApp.newTrigger('sendAgain').timeBased().after(130 * 1000).create();   // через 2 минуты проверить, были ли ещё правки
}

function sendAgain(e) {                          // одноразовый триггер: удаляет себя и при необходимости шлёт ещё один сигнал
  ScriptApp.getProjectTriggers().forEach(function (t) {
    if (t.getHandlerFunction() === 'sendAgain' && (!e || t.getUniqueId() === e.triggerUid)) ScriptApp.deleteTrigger(t);
  });
  if (CacheService.getScriptCache().get('again')) sendSignal();
}
```

Ключ хранится только в свойствах скрипта. Никогда не вписывайте его в код скрипта, в таблицу и в файлы сайта: всё, что лежит в репозитории,
видно всем в интернете. Ключ могут увидеть редакторы таблицы (у них есть доступ к скрипту). Если ключ попал не в те руки — удалите его на GitHub
(Developer settings → Personal access tokens → токен → Delete) и создайте новый. Через год срок ключа закончится: создайте новый и обновите свойство `GITHUB_TOKEN`.

## Social Media Challenge и достижения
- **Social Media Challenge (SMC)** – 4-й этап сезона по п. 5.2 регламента. Карточка в «Событиях» задана в `assets/js/data.js` (константа `SMC`: сроки 23.09.2026–25.01.2027, ссылка на папку приложения № 7 с условиями участия и заданиями); после даты окончания она исчезает сама, а если в таблице появится строка «Social Media Challenge», встроенная карточка скрывается, чтобы не было дубля. Если появится отдельная форма заявки, впишите её адрес в `SMC.url`.

## Новая таблица на следующий сезон
Проще всего не менять таблицу: добавьте в ту же таблицу вкладки нового сезона, а вкладки прошлого скройте (скрытые вкладки сайт не читает).
Если всё же нужна другая таблица, хаоса не будет — сайт привязан к ней одной строкой:
1. Откройте новой таблице доступ «Все, у кого есть ссылка — читатель».
2. В файле `tools/config.json` замените значение `sheet_id` на ID новой таблицы (часть адреса между `/d/` и `/edit`)
   и нажмите **Commit changes**. Через 1–2 минуты сайт возьмёт события из новой таблицы; события старой с сайта исчезнут.
3. В новой таблице у вкладок событий должна быть такая же строка-шапка, как сейчас: «Атауы / Название», «Қала / Город», «Облыс / Область»,
   «Күні / Дата», «Статус», «Өзгеріс / Изменения» и колонки категорий (FLL-D, FLL-E, FLL-C, FTC, …). Порядок колонок любой.
   Вкладки «Сайт» и «Новости» создайте заново или скопируйте из старой таблицы (правый клик по вкладке → Копировать в…).
4. Если было настроено мгновенное обновление (раздел выше), повторите его шаги 2–4 в новой таблице: скрипт живёт внутри таблицы,
   в старой его можно удалить. Ежечасная проверка работает в любом случае.

## Если запуск в Actions отмечен красным или жёлтым
Откройте **Actions → «Обновление сайта»**, затем нужный запуск. Сайт публикуется даже когда таблица или Telegram недоступны: тогда он показывает прежние данные, а запуск помечается жёлтым предупреждением.
- Предупреждение «Данные не обновились», в шаге «Загрузить расписание…» написано «таблица не открылась» — откройте таблицу → **Share** → «Все, у кого есть ссылка — читатель», затем **Run workflow**.
- Там же написано «в таблице N событий вместо M» — в таблице удалили много строк; сайт оставил прежнее расписание. Проверьте таблицу и запустите **Run workflow**.
- Предупреждение «Данные не сохранены в репозитории» — кто-то правил файлы в `assets/data/` вручную. Ничего делать не нужно, следующий запуск всё перезапишет. Эти файлы вручную не редактируйте.
- В шаге «Загрузить расписание…» есть строки «вкладка «Сайт»: …», «вкладка «Новости»: …», «логотип не скачался» или «фото новости не скачалось» —
  в таблице опечатка в названии параметра, ссылка не на разрешённый сайт или картинка недоступна (нет доступа по ссылке). Остальное обновилось;
  исправьте ячейку — следующий запуск подхватит. Пока вкладка «Сайт» не читается, сайт показывает прежние настройки сезона.
- Красный запуск с текстом «Get Pages site failed … Not Found» — не выполнен шаг 3 (Settings → Pages → Source: GitHub Actions). Выполните его и нажмите **Run workflow**.
- Серый запуск «Canceled» сразу после нескольких правок подряд — это нормально: публикуется самый новый.
- Письмо от GitHub «Scheduled workflow disabled due to inactivity» (приходит, если в репозитории 60 дней ничего не менялось) — откройте **Actions → «Обновление сайта» → Enable workflow**. Любая ваша правка файлов тоже снова включает расписание.

## Где что менять вручную
- Тексты, программы (`PROG`), статистика (`KS`, `GS`), достижения (`W`), главные новости-результаты (`N`), партнёры, ссылки на правила (`RULES`) — `assets/js/data.js`
  (на GitHub: открыть файл → значок карандаша → **Commit changes**; сайт обновится сам).
  Название и тему сезона, логотип, видео, ссылки на правила, письмо и расписание удобнее задавать во вкладке «Сайт» таблицы — заполненные там значения
  имеют приоритет над `data.js`.
- Хэштег для новостей и канал Telegram — `tools/config.json`.
- Оформление — `assets/css/style.css`, фото и логотипы — `assets/img/`.
- Шрифт: на Mac и iPhone сайт использует системный SF Pro (как firstrobotics.kz), на Windows и Android — Inter (подключён из Google Fonts). Меню разделов в шапке на компьютере — список ссылок в `index.html` (`#nav`), на телефоне оно же открывается по значку меню.
- `assets/data/` заполняется автоматически, вручную не редактировать.

Языки: қазақша (по умолчанию), русский, English. Ссылка сразу на нужный язык: `?lang=ru` или `?lang=en`. Выбранный язык запоминается в браузере посетителя.
